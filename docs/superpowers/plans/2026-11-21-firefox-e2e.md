# Firefox End-to-End Coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the Firefox Playwright smoke into a real end-to-end play session that drives the rendered UI against the authoritative server, proving the core gameplay loop under Gecko.

**Architecture:** A separate Python Playwright script (Gecko does not speak CDP) starts the real server with a temporary PGlite data dir, serves the built client, and drives the same rendered controls the Chrome/Edge e2e uses. Reuse the existing Playwright smoke helper patterns and the client's real DOM; no client changes, no second renderer.

**Tech Stack:** Python Playwright 1.60 (Firefox 150.0.2 provisioned), real Node server, Node test runner gates.

**Spec:** `docs/GOAL.md` (autonomous roadmap, Group C); `docs/ROADMAP.md` G5 Firefox/Safari item; `scripts/e2e-test.mjs` as the reference session.

## Global Constraints

- Firefox only. Safari/WebKit and devices stay NOT RUN; the G5 checkbox stays open because it also names Safari.
- Drive rendered controls, not internal request builders. Do not fabricate outcomes, skip timers or weaken assertions.
- No runtime dependency added to the shipped client. No protocol change.
- All GOAL §7 gates and the existing Chrome/Edge e2e/smoke stay green. 401-item roadmap accounting unchanged.

## Review Focus

- Is the session genuinely against the real server with registration and a persisted credential?
- Does the player complete build/collect/train/quest/reward through the DOM?
- Is the tutorial completed through the rendered overlay, not a debug hook?
- Are failures (refusals, replay) surfaced and asserted?
- Is the result labelled Firefox-only with Safari/not-run explicit?
