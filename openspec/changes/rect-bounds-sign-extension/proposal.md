# Proposal

## Why

`convert_building.parse_rect_bits` (`tools/asset-registry/convert_building.py:257-267`) decodes a
SWF `RECT`'s four coordinate fields with `BitReader.read_bits`, which is **unsigned** MSB-first, but
the format specifies those fields as **signed** (`SB`) bit fields. Reading them unsigned produces
inverted rectangles that no encoder emits, and the `max(0, ...)` clamp at `:267` then floors
`width_px`/`height_px` at zero, so the corruption is silently absorbed instead of surfacing as a
failure. Across the whole converted population this affects **2445 of 4347 shapes in 74 of 290
targets**.

This is the defect located and measured in `docs/legacy-m12-signed-rect.md` §4. It is worth a line
because it is one function, fully identified, causally closed, and bounded to committed files.

## What Changes

- **Sign-extend the four RECT fields** in `parse_rect_bits` instead of reading them unsigned.
- **Fail closed on an inverted RECT** (`xmax < xmin` or `ymax < ymin`) instead of clamping, replacing
  the `max(0, ...)` at `:267`.
- **Make the test fixture encoder spec-conformant**: `rect_bytes` in both converter test modules
  currently sizes its `Nbits` from the *unsigned* bit length, so two of the three crafted RECTs
  declare a field too narrow to hold their own values as signed. Widen by one bit; **no test
  expectation value changes**.
- **Regenerate the one affected committed package**, `assets/converted/units/10033_wild_elephant/package.json`.

Not breaking in the compatibility-API sense: no route, envelope, or client-visible contract changes.
It **is** breaking for one committed package's bytes, which is the point of the correction.

### Measured evidence

All figures below were measured on this repository at pinned CPython 3.9.13, routing every target
through the correct per-domain converter via `census_targets.CONVERTER_BY_DOMAIN`.

| Measurement | Result |
| --- | --- |
| Population | 290 converted targets, 4347 shapes |
| Shapes decoding inverted (`xmax < xmin` or `ymax < ymin`), unsigned | **2445** |
| Targets affected | **74** |
| Inversions remaining after sign extension | **0** |
| Targets still parsing after sign extension | **290 / 290** |
| Shapes whose count changes | **0** |
| Per-field moves: `xmin` / `ymin` | 1987 / 1597 |
| Per-field moves: `xmax` / `ymax` | 10 / 22 |
| Per-field moves: `width_px` / `height_px` | 10 / 22 |
| Targets with a size field moving | 13 |
| Direction of all 32 size moves | non-zero → 0 (0 of them zero → non-zero) |

Committed output, converted under both parsers and diffed field by field:

| Committed package | Shapes | Shapes moved | `width_px`/`height_px` moved | Non-shape fields changed |
| --- | --- | --- | --- | --- |
| `assets/converted/buildings/0001_house_1_m` | 1 | **0** | **0** | **0** (byte-identical) |
| `assets/converted/units/10033_wild_elephant` | 28 | **19** (`xmin` 9, `ymin` 17) | **0** | **0** |

So the only committed change is an **origin-only** correction: no size and no non-shape field moves.

Test impact, measured as three in-process A/B variants of the two converter suites, each in its own
process so no state leaks between them:

| Variant | RECT parser | fixture encoder | Result |
| --- | --- | --- | --- |
| Z (true baseline) | committed | committed | 81 tests, **0 failures / 0 errors** |
| A | sign-extended | committed | 70 run, **9 failures / 2 errors** (11 tests never ran) |
| B | sign-extended | spec-conformant | 81 tests, **0 failures / 0 errors** |

Variant A is what makes the fixture amendment necessary rather than optional: `rect_bytes(200, 100)`
declares `Nbits = 8` while carrying 200 (sign bit 128), and `rect_bytes(2000, 2000)` declares
`Nbits = 11` while carrying 2000 (sign bit 1024). Neither value is representable in the signed field
the fixture itself declares, so the crafted fixtures were relying on the defect. Variant B restores
the full 81 tests green **with not one expectation value changed**.

## Capabilities

**Modified Capabilities**

- `first-building-conversion` — *Requirement: Shape-style record parsing*. The RECT decoding rule and
  the inverted-rect refusal are spec-level behaviour, not implementation detail.
- `first-unit-conversion` — *Requirement: Shape records with byte-aligned style arrays*. This
  requirement already names "the shared style parser", and `convert_unit.py:362` calls
  `shared.parse_shape_with_style`, so unit targets are governed by the same rule.

**New Capabilities**: none.

## Non-goals

- **`width_px`/`height_px` from the far edge (D2) is deferred to a separate change.** It is separable
  and measured (3452 of 4347 shapes, 76 of 290 targets, measured against the true extent only), but it
  is a different behavioural decision. This change's interaction with it is recorded in `design.md`.
- **No mass conversion.** The 290 packages are not regenerated by this change; only the one committed
  package whose bytes change. Mass conversion remains an open, unauthorised decision.
- **No reinterpretation of what a RECT means for rendering, layout, or footprint.** The pixel sizes
  keep their existing origin-relative definition.
- **No change to the census verdict set**, the registry, coverage, inspection, or extraction manifests.

## Impact

- **Code**: `tools/asset-registry/convert_building.py` (`parse_rect_bits`, ~11 lines).
- **Tests**: `tools/asset-registry/tests/test_convert_building.py` and
  `tools/asset-registry/tests/test_convert_unit.py` — the `rect_bytes` fixture encoder only.
- **Generated output**: `assets/converted/units/10033_wild_elephant/package.json` (19 of 28 shapes'
  `xmin`/`ymin`).
- **Derived manifests**: `tools/asset-registry/conversions.json` (the elephant's `output_bytes`
  384701 → 384684 and its `package_sha256`, plus the aggregate `counts.output_bytes`), and — as a
  consequence of that — `tools/asset-registry/asset_ids.json`, which hashes `conversions.json` as a
  recorded input. **Added during Apply:** the original Impact list omitted `asset_ids.json` and no
  task covered regenerating it, so the full `tools/asset-registry/tests` discovery failed on
  `test_build_asset_ids.RebuildDeterminismTests.test_rebuild_matches_committed_bytes` until it was
  regenerated. Its diff is **one** input digest (`conversions.json`), with every other recorded input
  and every count unchanged. `statuses.json` did not change.
- **Capabilities**: `first-building-conversion`, `first-unit-conversion` (both modified).
- **Unaffected**: `legacy-manifest.json` does not cover `assets/converted`, so the 3258-entry
  preservation manifest is unaffected. No SWF, save, config, village, or legacy source byte changes.
- **Consumed by**: the Godot client's `godot-unit-animations` and `godot-town-rendering` linkage
  reads, which see `bounds` as package data. This change makes those reads correct rather than
  changing their contract.
