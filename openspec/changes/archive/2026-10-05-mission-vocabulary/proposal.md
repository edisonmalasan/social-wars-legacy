# Proposal

## Why

M10's first objective in roadmap order is *mission loading / mission state*. The
committed investigation (`docs/legacy-m10-missions.md`, PR #283) measured that
objective and found its premise wrong in a useful way:

- **Mission state is already delivered.** The legacy server has **exactly one**
  mission-mutating command, `collect_mission` (`command.py:430-442`), and the M9
  `godot-quests` line delivers it with a captured executed-legacy fixture at
  `tests/fixtures/godot-quests/steps/command_collect_mission/` and two spec
  requirements naming its stringification divergence. The only other mission
  write, `command.py:111` inside `set_quest_var`, is delivered by the same line.
- **Mission loading has no oracle.** There is no mission-loading command, and
  **all ten** committed save documents hold `maps` of length **1** with
  `default_map` `0`. A "mission" here is a single integer chapter counter on the
  player's own map, not a place to load.
- **Both mission save fields are write-only.** `idCurrentMission` has 2 writes and
  0 reads; `timestampLastChapter` has 2 writes and 0 reads, and its second write
  is inside `fast_forward`, which subtracts a **client-supplied** number of
  seconds.

So the state and loading halves are closed. What remains undelivered is
**vocabulary rather than behaviour**:

- **64** `MISSION_*` constants at `constants.py:984-1047`, with 64 distinct values
  spanning `0..67`, no duplicates, and **four numbering gaps at `9`, `10`, `20`,
  `57`**;
- **three** committed mission-adjacent globals the normalized package already
  carries and nothing reads — `NUM_ACTIVE_MISSIONS` = `5`, `PERMISSION_PACK_UNITS`
  = `[10,20,30,40]`, `PERMISSION_COSTS` keys `10,20,30,40`;
- **zero** `MISSION_*` occurrences anywhere outside `constants.py` itself.

That vocabulary is not inert documentation. It is the game's **client-event
vocabulary**, and it **names the combat events the game recognised** —
`MISSION_ATTACK_PLAYER` (37), `MISSION_ATTACK_FRIEND` (38),
`MISSION_ASSAULTS_WON` (46), `MISSION_KILLED_ENEMY` (67),
`MISSION_DEFEAT_ALL_TROLLS` (30), `MISSION_CAPTURED_SUBCATFUNC`/`_ID` (11, 12),
`MISSION_SACRIFICE_UNIT` (63) and eight more. Delivering it now is what lets M10's
later combat lines say *"the oracle named this event and never implemented it"*
instead of inventing a trigger.

## What Changes

- **NEW capability `godot-mission-vocabulary`.** A typed, read-only projection of
  the 64 committed `MISSION_*` constants and the three committed
  mission-adjacent globals, reporting names, values, ordering and numbering gaps
  **verbatim**, with the zero-consumer finding recorded **structurally** rather
  than only asserted.
- A committed, **drift-guarded** vocabulary table plus a test that asserts it is
  byte-faithful to `constants.py`, so transcription cannot rot.
- A deterministic `mission-vocabulary-report-v1` evidence report generated by the
  suite from the projection's own data.

## Impact

- **Affected specs:** one new capability. `godot-quests` is **read but not
  modified** — it owns the mission *state* fields, and this line must not
  duplicate or reconcile them.
- **Affected code:** the Godot client only, plus one new hermetic suite and one new
  test file. **No Compatibility API endpoint, no executed-legacy fixture, and no
  live phase**, because there is no behaviour to exercise — the same finding that
  removed the fixture from M8's movement and animations lines.
- **No content-package change.** The normalized package is **not** extended to
  carry legacy `constants.py` vocabulary; see design decision 1.
- Blast radius is small and bounded: content projection, no state mutation, no
  network, no save write.

## Non-goals

This line deliberately delivers **no**:

- mission-loading mechanism (no oracle exists);
- mission completion, reward, or unlock rule (the vocabulary has zero consumers,
  and the M9 lesson is that inventing a schedule is not a migration);
- enforcement of `NUM_ACTIVE_MISSIONS` (committed, unread);
- a map-index bounds refusal for `command.py:37` (recorded, not invented);
- any second capture of `collect_mission` (already captured by `godot-quests`);
- any behaviour, trigger, or dispatch keyed on a mission type.
