# Proposal

## Why

M12's `asset-package-parameterisation` line (PR #350, merged `9c7e35e`) closed with an explicit
non-goal: *"No mass conversion. 290 packages are available; committing them is roughly 15,000 files
and a preservation-manifest regeneration."* That estimate was never measured. Objective 1
(`docs/legacy-m12-byte-alignment.md`, PR #371) resolved the byte-alignment rule from the authority
and Objective 2 (`docs/legacy-m12-scope-classes.md`, PR #372) measured the cost of lifting the three
scope-decision refusals. Neither touched this deliverable, so it is still open and it is the last
substantive M12 deliver item.

I measured it before proposing, and **the measurement falsifies the estimate on both counts.**

### 1. The output is 8,805 files and 72.9 MB, not ~15,000 files

I ran the committed census harness (`census_targets.evaluate`) over all **290** census-convertible
targets into a disposable temp root, read-only with respect to the repository. Every target was
evaluated; **0** raised; **0** disagreed with the committed census verdict.

| | measured |
|---|---|
| targets evaluated | **290** (222 buildings, 68 units) |
| `package.json` files | **290** (9,034,706 bytes) |
| bitmap files | **8,515** (63,853,466 bytes) |
| **total** | **8,805 files / 72,888,172 bytes** |

So **8,805**, not ~15,000. The committed census is the scope authority and it is correct; the
estimate in the non-goal was not.

### 2. The preservation manifest cannot be regenerated by this line, and the claim is withdrawn

The non-goal said this work includes *"a preservation-manifest regeneration"*. **That is false and I
withdraw it.** `hash_manifest.py:180-184` builds from `git ls-tree -r <commit>` — a **fixed
commit**, recorded in the document as `source.commit = e8c98a03c902eba70323538dc5d4eaba2f2927a1`.
New files cannot enter it. Measured: the committed manifest has **3,258** entries and **0** under
`assets/converted`, even though two converted packages are already committed and `assets` is a
`PROTECTED` root (`:16-17`).

`assets` being protected is what made this look true, and it is why the claim is worth recording
rather than quietly dropping: protection governs what the manifest *would* hash **if the pinned
commit contained those blobs**, not what a later commit adds. The regeneration is impossible, not
merely unnecessary.

### 3. The bitmap bytes are copies, and they are 88% of the cost

The converters do not reference extracted bitmaps — they **copy** them into the package directory
(`convert_building.py:796-797`, `convert_unit.py` likewise), taking only the basename
(`:725-726`). Those bytes already exist on disk under `assets/converted/images/`, which **is**
gitignored.

So the 63.9 MB is not new asset content; it is a second copy of material already extracted and
already ignored. Measured cross-package duplication is only **1.11×** (7,275 distinct bitmap
contents across 8,515 occurrences), so deduplication is not the lever — the copy itself is.

**Decision taken (user-confirmed): commit the 290 `package.json` manifests and have each record
reference the shared extracted tree instead of copying bytes per package.** This adds ~9 MB, mostly
text, and is reversible. Committing 63.9 MB of duplicate binaries into a `.git` already at
**690 MB** is not reversible without a history rewrite, which preservation rules forbid.

### 4. What referencing instead of copying actually changes

This is a contract change, not a repackaging, and the line must say so plainly:

- **The package schema changes shape.** `building_package.schema.json:78-82` declares `bitmaps` as
  an array of opaque objects, so the *shape* survives; but each entry's `file` currently names a
  path **inside the package directory**. Referencing means `file` names a path under
  `assets/converted/images/<sprite>/`.
- **`conversions.json`'s `output_bytes` stops meaning what its description says.**
  `conversion.schema.json:72-74` defines it as *"Package.json bytes plus **copied** bitmap bytes"*.
  With no copies it becomes the package.json byte total. The schema description must be amended in
  the same change, or the document will assert something false.
- **The client resolves bitmaps relative to the package directory.** `package_paths.gd:33-38`
  resolves package-relative paths via `repo_root()`, and `package_loader.gd:481` iterates
  `data["bitmaps"]`. Whether it treats `file` as package-relative or repository-relative decides if
  this is a one-line resolution change or a client contract change. **I have not yet measured
  which**, and the design must not assume the cheap answer.
- **`verify.ps1` hashes both package directories** (`package_paths.gd:11-14`, `verify.ps1:184-185`).
  If bitmaps leave the package directories, those digests change — and they are pinned in
  `evidence/first-render/report.json` and `test_package_loader.gd`.

### 5. The latent MATRIX anomaly will be embedded in 290 committed packages

Objective 2 recorded, and deliberately did not act on, that captured MATRIX bytes decode in the
committed parser's own MSB-first order to `HasScale = 1` and `NScaleBits = 22` against a format cap
of 11 — in **2,869 / 2,869** resolvable bitmap fills. `parse_matrix` (`:296-308`) validates nothing,
so it is consumed silently. Objective 3 embeds those bytes into 290 packages.

**Decision taken (user-confirmed): proceed, record the anomaly at line level, and preserve the
captured hex verbatim.** No per-package anomaly field is invented — that would be a new format claim
over bytes whose meaning is not established. This is not a new investigation line; the standing
investigate-only instruction on the desync family is untouched.

## What Changes

1. **Both converters stop copying bitmap bytes and reference the shared extracted tree.** Each
   `bitmaps[].file` records the extraction output path under `assets/converted/images/<sprite>/`,
   keeping `sha256` and `bytes` so the reference is verifiable without the copy. The digest check
   at `:736-738` is retained — it is what proves the referenced bytes are the intended bytes.
2. **`conversions.json`'s `output_bytes` semantics are corrected** in the schema description to the
   package.json byte total, and the two committed package entries are re-derived under it.
3. **The 290 census-convertible targets are converted**, and their `package.json` manifests are
   committed under `assets/converted/buildings/` and `assets/converted/units/`.
4. **The client and `verify.ps1` are updated for the resolved bitmap path form**, and every pinned
   digest that moves is updated in the same change.
5. **The MATRIX anomaly is recorded** in the change's own artifacts as carried-forward and
   unresolved, with the measurement quoted.

## Non-goals

- **No refusal class is lifted.** All **527** refused targets stay refused. Objective 2 established
  that the largest class (`unresolvable bitmap fill`, 133) is **not** a scope decision and cannot be
  resolved by any parser or extractor change; lifting it would ship dangling references.
- **No bitmap bytes are committed**, and no `assets/converted/images/` path is un-ignored.
- **No preservation-manifest change** — it is impossible, per §2.
- **No change to the parsed subset**, the `conversion-v1` policy identifiers, or the
  `asset-package-census` capability's verdict semantics.
- **No client-visible rendering.** The client still pins two packages; this line changes no scene,
  no capture, and no pixel claim.
- **No Flash, Ruffle, ActionScript, or browser execution**, and no network access.
- **No desync-family line**, per the standing investigate-only instruction.

## Impact

- `tools/asset-registry/convert_building.py`, `convert_unit.py` — output form only.
- `tools/asset-registry/schemas/conversion.schema.json` — `output_bytes` description.
- `assets/converted/buildings/**/package.json`, `assets/converted/units/**/package.json` — **290 new
  manifests (~9 MB), plus 2 re-derived.**
- `tools/asset-registry/conversions.json`, `statuses.json` — regenerated.
- `apps/client-godot/scripts/package_paths.gd`, `package_loader.gd`, `tests/test_package_loader.gd`,
  `verify.ps1`, and the pinned digests in `evidence/first-render/report.json` — **conditional on the
  §4 resolution measurement, which is an Apply-stage task, not an assumption here.**
- Preserved inputs — sprites, extracted bitmaps, inspection and extraction manifests, normalized
  content, saves, config, villages — are **read-only** and must remain byte-identical.
